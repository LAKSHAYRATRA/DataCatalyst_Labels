3. SCOPES OF IMPROVEMENT / SUGGESTIONS
------------------------------------------------------------------------
* Offline Transliteration Fallback:
  - Currently, suggestion mode relies entirely on the external Google Input Tools API. Implementing a simple, local, offline rule-based or dictionary-based transliteration library as a fallback would ensure the editor functions even if offline or if the API is rate-limited.
* Pre-calculated Waveform Peaks:
  - When loading very long audio files, generating the waveform using client-side Web Audio can lag or use a lot of memory. Generating and sending pre-calculated peak data from the Node backend would make loading instant.
* Edit Conflict Prevention:
  - If multiple editors open the same project session, their changes could overwrite each other. Adding a simple WebSocket connection to lock a session while an editor is actively working would prevent conflicts.
* Visual Timing Warning Indicators:
  - Add visual flags on the waveform (e.g. highlighting in red) when word boxes overlap, are too short (< 50ms), or have gaps larger than a second, so editors can spot alignment anomalies faster.
